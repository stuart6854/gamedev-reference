# Source generators

A source generator adds C# files to a compilation while it is being built. This page builds one with the incremental API: fields marked `[Notify]` get a property that raises an event when its value changes.

```csharp
// Written by hand
public partial class PlayerStats
{
    [Notify] int _health;
    [Notify] string _name = "";
}

// Generated
partial class PlayerStats
{
    public event global::System.Action<string>? PropertyChanged;

    public int Health
    {
        get => _health;
        set
        {
            if (global::System.Collections.Generic.EqualityComparer<int>.Default.Equals(_health, value)) return;
            _health = value;
            OnHealthChanged(value);
            PropertyChanged?.Invoke(nameof(Health));
        }
    }

    partial void OnHealthChanged(int value);
    // ... and the same for Name
}
```

The generated `partial void` method is optional to implement. If the class defines `OnHealthChanged`, it runs on every change; if not, the compiler removes the call.

## Incremental generators

The original `ISourceGenerator` interface ran its whole `Execute` method on every change, which in an IDE means every keystroke. It is deprecated. `IIncrementalGenerator` instead describes a **pipeline**: a chain of steps whose results the compiler caches, and re-runs a step only when its input has changed.

```csharp
[Generator]
public sealed class NotifyGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // Pipeline steps go here. Initialize runs once; the steps run per compilation.
    }
}
```

The pipeline is built from providers:

| Step | Does |
| --- | --- |
| `context.SyntaxProvider.ForAttributeWithMetadataName` | Nodes carrying a given attribute. The fast, preferred entry point. |
| `context.SyntaxProvider.CreateSyntaxProvider` | Any nodes, chosen by a predicate. Slower; use when there is no attribute to look for. |
| `context.AdditionalTextsProvider` | Non-code files passed to the compiler. |
| `context.CompilationProvider` | The whole compilation. Changes on every edit. |
| `.Select`, `.Where`, `.SelectMany` | Transform, filter, or flatten values. |
| `.Collect()` | Gather many values into one `ImmutableArray`. |
| `.Combine(other)` | Pair each value with another provider's value. |
| `RegisterSourceOutput` | The end of a pipeline: write files and report diagnostics. |
| `RegisterPostInitializationOutput` | Add fixed source once, before anything else. Used for the attribute itself. |

### The caching rule

The cache works by comparing each step's output with its output last time. If they are equal, everything downstream is skipped. So:

- **Every value passed between steps must have value equality.** Records do, as long as everything inside them does. Arrays and `ImmutableArray<T>` do not; wrap them in an [`EquatableArray<T>`](#equatablearray).
- **Never put Roslyn objects in a model**: no `ISymbol`, `SyntaxNode`, `SemanticModel`, `Compilation`, or `Location`. They are never equal between compilations, so the cache never hits, and they keep whole old compilations alive in memory. Copy out the strings and numbers you need.
- **Avoid `CompilationProvider`**, and anything combined with it. It changes on every keystroke, so it defeats the cache for everything downstream. If you need a fact from the compilation, such as whether a type exists, `Select` it down to a `bool` or a string first.

## The attribute

The generator adds its own attribute to every compilation it runs in:

```csharp
const string AttributeSource = """
    // <auto-generated/>
    namespace GameTools
    {
        [global::System.AttributeUsage(global::System.AttributeTargets.Field)]
        internal sealed class NotifyAttribute : global::System.Attribute { }
    }
    """;

context.RegisterPostInitializationOutput(static ctx =>
    ctx.AddSource("GameTools.NotifyAttribute.g.cs", AttributeSource));
```

`internal` gives each assembly its own copy, so assemblies that reference each other do not see two public `GameTools.NotifyAttribute` types (warning CS0436). The alternative is a small runtime library that defines the attributes, referenced by every assembly that uses them.

Write `global::` before every type name in generated code. The user's project might have its own `System` namespace or `Action` class.

## Finding the fields

```csharp
var fields = context.SyntaxProvider.ForAttributeWithMetadataName(
        "GameTools.NotifyAttribute",
        predicate: static (node, _) => node is VariableDeclaratorSyntax,
        transform: static (ctx, _) => ToModel((IFieldSymbol)ctx.TargetSymbol))
    .Where(static m => m is not null)
    .Select(static (m, _) => m!);
```

`ForAttributeWithMetadataName` uses an index the compiler keeps of attribute names, so it only looks at nodes whose attributes could match. On a field declaration it reports each variable (`int _a, _b;` is two), which is why the predicate checks `VariableDeclaratorSyntax`.

The transform is the one place with access to symbols. It copies what the output needs into a model and drops everything else:

```csharp
record FieldModel(
    string Namespace, string TypeName, string TypeKeyword,
    string FieldName, string PropertyName, string FieldType);

static FieldModel? ToModel(IFieldSymbol field)
{
    INamedTypeSymbol type = field.ContainingType;
    if (type.ContainingType is not null || type.IsGenericType)
        return null;        // not supported; the analyser reports it

    string ns = type.ContainingNamespace.IsGlobalNamespace
        ? ""
        : type.ContainingNamespace.ToDisplayString();

    return new FieldModel(
        ns,
        type.Name,
        type.TypeKind == TypeKind.Struct ? "struct" : "class",
        field.Name,
        PropertyName(field.Name),
        field.Type.ToDisplayString(SymbolDisplayFormat.FullyQualifiedFormat));
}

internal static string PropertyName(string field)       // shared with the analyser
{
    string s = field.StartsWith("m_") ? field.Substring(2) : field.TrimStart('_');
    return s.Length == 0 ? field : char.ToUpperInvariant(s[0]) + s.Substring(1);
}
```

`SymbolDisplayFormat.FullyQualifiedFormat` writes types as `global::System.Collections.Generic.List<global::Game.Item>`, which compiles anywhere the generated file ends up.

## Grouping by type

Each type gets one file, holding every property and a single `PropertyChanged` event, so the fields are collected and grouped:

```csharp
record TypeModel(
    string Namespace, string TypeName, string TypeKeyword,
    EquatableArray<FieldModel> Fields)
{
    public string HintName =>
        (Namespace.Length > 0 ? Namespace + "." : "") + TypeName + ".Notify.g.cs";
}

var types = fields
    .Collect()
    .SelectMany(static (all, _) => all
        .GroupBy(f => (f.Namespace, f.TypeName))
        .Select(g => new TypeModel(
            g.Key.Namespace, g.Key.TypeName, g.First().TypeKeyword,
            new EquatableArray<FieldModel>(g.OrderBy(f => f.FieldName).ToImmutableArray()))))
    .WithTrackingName("NotifyTypes");

context.RegisterSourceOutput(types, static (spc, type) =>
    spc.AddSource(type.HintName, Emit(type)));
```

`Collect` re-runs the grouping whenever any field changes anywhere, which is cheap. `SelectMany` then compares each `TypeModel` with last time's, so `Emit` only runs for the types whose fields actually changed. Sorting the fields keeps the output stable when files are processed in a different order.

`WithTrackingName` names the step, so a test can [check that it was cached](testing.md#checking-the-cache).

Hint names must be unique within the generator, and are used as file names. Include the namespace so two `PlayerStats` types in different namespaces do not collide.

## Writing the source

```csharp
static string Emit(TypeModel type)
{
    var sb = new StringBuilder();
    sb.AppendLine("// <auto-generated/>");
    sb.AppendLine("#nullable enable");
    if (type.Namespace.Length > 0)
        sb.AppendLine($"namespace {type.Namespace}").AppendLine("{");

    sb.AppendLine($"partial {type.TypeKeyword} {type.TypeName}");
    sb.AppendLine("{");
    sb.AppendLine("    public event global::System.Action<string>? PropertyChanged;");

    foreach (FieldModel f in type.Fields)
    {
        sb.AppendLine($$"""

                public {{f.FieldType}} {{f.PropertyName}}
                {
                    get => {{f.FieldName}};
                    set
                    {
                        if (global::System.Collections.Generic.EqualityComparer<{{f.FieldType}}>.Default.Equals({{f.FieldName}}, value)) return;
                        {{f.FieldName}} = value;
                        On{{f.PropertyName}}Changed(value);
                        PropertyChanged?.Invoke(nameof({{f.PropertyName}}));
                    }
                }

                partial void On{{f.PropertyName}}Changed({{f.FieldType}} value);
            """);
    }

    sb.AppendLine("}");
    if (type.Namespace.Length > 0)
        sb.AppendLine("}");
    return sb.ToString();
}
```

- `// <auto-generated/>` tells analysers (and the IDE's style rules) to skip the file.
- `#nullable enable` is needed in every generated file that uses `?` on reference types, because generated files ignore the project's nullable setting.
- The raw string literal (`$$"""`) is C# 11, but it only exists in the generator. The text it produces is plain C# 9, which Unity can compile.
- The partial declaration has no access modifier, so it takes whatever the user's declaration has.

## EquatableArray

`ImmutableArray<T>` compares by reference, so a model holding one is never equal to last time's copy. Wrap it:

```csharp
public readonly struct EquatableArray<T> : IEquatable<EquatableArray<T>>, IEnumerable<T>
    where T : IEquatable<T>
{
    readonly T[]? _items;

    public EquatableArray(ImmutableArray<T> items) =>
        _items = items.IsDefaultOrEmpty ? null : items.ToArray();

    public int Count => _items?.Length ?? 0;

    public bool Equals(EquatableArray<T> other)
    {
        T[] a = _items ?? Array.Empty<T>();
        T[] b = other._items ?? Array.Empty<T>();
        if (a.Length != b.Length) return false;
        for (int i = 0; i < a.Length; i++)
            if (!a[i].Equals(b[i])) return false;
        return true;
    }

    public override bool Equals(object? obj) => obj is EquatableArray<T> other && Equals(other);

    public override int GetHashCode()
    {
        unchecked
        {
            int hash = 17;
            foreach (T item in _items ?? Array.Empty<T>())
                hash = hash * 31 + item.GetHashCode();
            return hash;
        }
    }

    public IEnumerator<T> GetEnumerator() =>
        ((IEnumerable<T>)(_items ?? Array.Empty<T>())).GetEnumerator();

    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}
```

Records implement `IEquatable<T>`, so a record of strings, numbers, and other `EquatableArray`s is safe to pass through the pipeline.

## Reporting problems

A generator can report diagnostics from `RegisterSourceOutput` with `spc.ReportDiagnostic`. Keep that for problems the generator meets while generating, such as a malformed [data file](generator-examples.md#generating-from-a-data-file). Rules about how the user wrote their code (the type is not `partial`, the field is `readonly`) belong in an [analyser](analyzers.md#rules-for-the-generators-attributes):

- Analysers run in the IDE as you type, with their own caching, and can be configured per rule.
- Reporting a diagnostic needs a `Location`, which cannot be stored in a model. A generator has to store the file path and span and rebuild the `Location`, which is awkward.
- The generator stays simple: on input it cannot handle, it generates nothing and returns.

## Debugging

- Read the generated files: `EmitCompilerGeneratedFiles`, or the IDE's analyser node (see [project setup](index.md#project-setup)).
- Write [tests](testing.md) that run the generator on a string of source code. It is much faster than rebuilding a project, and the debugger works.
- `System.Diagnostics.Debugger.Launch()` at the top of `Initialize` attaches a debugger to the compiler process. It works on Windows; remove it before shipping.
- An exception in a generator does not fail the build with a stack trace. It produces warning CS8785, "Generator failed to generate source", and the generator's output is missing, so every use of a generated member then fails to compile. Look for CS8785 first.
